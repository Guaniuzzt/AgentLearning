01

全局视图

ReActAgent 自己不写提示词、不发 HTTP 请求、不解析网页， 它只做一件事：把「拼提示 → 问模型 → 执行动作」串成循环。脏活由两个协作者承担。

模型层 HelloAgentsLLM

包装 OpenAI 兼容接口。athink() 异步流式，think() 同步兜底。

→
编排层 ReActAgent

持有 history 与 observations，跑七步循环，负责并发、超时、重试、降级。

→
工具层 ToolExecutor

登记「工具名 → 函数 + 参数模型」，用 Pydantic 校验参数。Search 背后是 DeepSeek Search。

两个状态容器

  • history：纯文本行，每轮追加 Action: 与 Observation:，下一轮原样拼回提示词。
  • observations：结构化记录，整体降级时只挑 status == "ok" 的条目拼答案。
  • 两者都只在 gather 返回后串行写入，所以不需要加锁。

为什么 Semaphore 在运行时创建

asyncio.Semaphore 会绑定创建时的事件循环。若放在 __init__， 同一个 Agent 实例第二次 asyncio.run() 就会因跨循环抛错。

所以它在 arun() 开头重建——每次运行都是干净的并发额度。

03

单次 Action 的三阶段

_execute_action()（L328）只做限流，真正的逻辑在 _execute_with_retry()（L339）。它保证一件事： 除取消外，永不抛异常，所有失败都变成一条可读的 ToolObservation。

参数校验：拦在工具执行之前

tool_executor.parseArgs() 用工具声明的 Pydantic 模型校验原始文本。 非法参数直接返回，工具函数一次都不会被调用。

单参数工具把整段文本映射到唯一字段；多参数工具要求模型输出 JSON。

ValidationError → status=invalid_args attempts=0（没跑过）

执行：超时 + 分类重试

asyncio.timeout(tool_timeout) 包住 _call_tool()： 协程工具直接 await，同步工具丢进 asyncio.to_thread。

失败按类型分流，这是「不浪费时间重试」的关键。

协程 → await 同步 → to_thread TimeoutError → 重试 ToolError(retryable=True) → 重试 ToolError(retryable=False) → 立即降级 CancelledError → 向上抛

降级：把失败写成一条 Observation

重试用尽后返回 status 为 timeout / error 的观察， 文案里明确写「已降级，请用已有信息继续推理」，ReAct 循环照常进入下一轮。

timeout / error 写回 history 不中断整个流程 
# 失败分类决定了「重不重试」，这是 _execute_with_retry 的核心
except TimeoutError:
    status = "timeout"          # 偶发，值得重试
except asyncio.CancelledError:
    raise                         # 取消不是失败，交给最外层
except ToolError as e:
    if not e.retryable:
        return ToolObservation(...)  # 鉴权 / 余额 / 4xx：立即降级
except Exception as e:
    status = "error"             # 未预料异常，同样重试

if attempt <= self.config.tool_retries:
    delay = 0.5 * attempt
    async with asyncio.timeout(delay + 1.0):  # 退避等待也要有上界
        await asyncio.sleep(delay)

限流位置的选择

临界区只包住「执行」这一步，不含拼提示、解析、写历史。 这样并发数严格等于同时运行的工具数，而不是含排队的调用数。

为什么不并发问模型

每一步都依赖上一步的 Observation，天然串行； 并发只发生在同一轮内部的多个独立工具之间。

注释索引

代码里的注释分两类：docstring 说明「这个函数负责什么、输入输出是什么、什么情况下会失败」， 行内注释 只解释「为什么这么写」——尤其是那些删掉就看不出来的坑。

ToolObservation.status

ok工具正常返回
invalid_argsPydantic 校验拦截，工具未执行
not_found注册表里没有这个工具名
timeout连续超时，重试已用尽
error异常或不可重试错误

四条退出路径

  • E1 拿到 Finish[...] → 返回答案（唯一正常出口）
  • D1 模型调用失败或超时 → 降级
  • D2 模型没给出合法 Action → 降级
  • D3 达到 max_steps → 降级

取消（CancelledError）的三条规矩

  • 只在 except asyncio.CancelledError: raise 里出现，绝不改写
  • 不被当成「工具失败」，不消耗重试次数
  • gather 会把取消传递给兄弟 Task，整轮一起退出

验证过的行为（离线假工具，不消耗搜索额度）

  • 8 个 Action 同轮并发、Semaphore=2 时实测最大并发为 2
  • 同步阻塞工具经 to_thread 正常返回，事件循环不卡
  • 抛异常的工具 attempts=2（重试一次）后降级；超时工具同样
  • 参数非法 attempts=0，工具函数未被调用
  • 外层 wait_for 取消 → TimeoutError 正确向上传播
  • 401（retryable=False）不重试，attempts=1 直接降级
